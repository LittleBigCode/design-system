# Corrections found during execution

Not a derived artifact. The four files beside this one are **copies** carrying a
provenance header, and correcting a measurement in a copy diverges it from the
source silently. This file is where a batch records what it found instead: a
source defect it fixed forward, or a measurement in the plan that execution
proved wrong.

The rule it serves is [`batch-plan.md`](./batch-plan.md) §"The source ref":
nothing unfreezes the pin, so a defect is fixed forward in the target, inside
the batch that hits it, and recorded here as one line. The accepted cost is that
source and target diverge with no trace outside this file.

One row per finding. `batch` is the batch that found it, not the one that owns
the surface.

| 4 | source defect, fixed forward | `sparkline.tsx` drew a flat series along the floor of its box rather than through the middle: every point equal makes the range zero, and the normalisation divided by it. Fixed in the absorbed component. |
| 4 | source defect, fixed forward | A focus ring that drew nothing — `outline: 2px solid transparent`, Tailwind's `outline-hidden` idiom — was bound to `:focus-visible` with the charte's real 2px outline. |
| 5 | plan measurement wrong | The dedupe-exception table gives batch 5 **5** exceptions across `funnel-chart`, `radar-chart`, `scatter-chart`, `treemap` and `waterfall-chart`. `bullet-chart.css` carries a sixth, in the same form and for the same reason (`[--bullet-label:7rem]` / `[--bullet-value:4rem]` kept literal so `tailwind-merge` could dedupe `in-table.tsx`'s override). The real count is **6**, and the plan's 36-owed total is **37**. All six are resolved in beta.5 — the rule is that an exception is never carried across, and the count is not what decides that. |
| 5 | source comment wrong, no fix needed | `funnel-chart.tsx` carries a comment saying recharts gates a funnel's labels behind `showLabels = !isAnimating`, that the animation therefore restarts forever, and that "with the animation off they render on the first paint" — and then sets no `isAnimationActive` anywhere in the source. Against the recharts this package pins, the labels render with animation on, so the component is absorbed unchanged and `site/tests/chart-marks.spec.ts` asserts the labels are present under animation, which is the one gate that opts back out of reduced motion. |
| 6 | plan question answered | The "one look owed" on `agenda` and `pagination` (batch-plan §4 batch 6, CSS ledger §6.2). **`agenda` is a strict superset** — same `events`/`emptyMessage` props and the same grouping and sorting, plus a `locale` the incumbent could not have (it hardcoded English weekday and month tables), plus `<section>`/`<h3>`/`<time datetime>` where the incumbent emitted a flat run of divs. **`pagination` is not a superset in shape but loses no capability**: the incumbent's `page`/`pageCount`/`onChange` disappear, but its window logic ships intact as the exported pure function `paginationRange()`, and the parts buy a page that can be a real `<a href>` — crawlable, middle-clickable — which the incumbent's buttons could not be. That is composition replacing configuration, which is the trade every applier in this migration makes, not a regression like #164's `time-picker`. Both land; both stylesheets replace. The recipe for rebuilding the controlled pager is in `docs/migration/from-0.11.md`. |
| 6 | plan item resolved early | The `kbd` / `input-group` cascade inversion (batch-plan §4 batch 6, source [#171](https://github.com/diamorval/design-system-diametral/issues/171)) is **fixed now rather than shipped inverted in beta.6 and beta.7**. The source layers `kbd.css` so `InputGroupAddon`'s Tailwind utility keeps outranking `background: var(--input)`; unlayered, the plain declaration would have won instead. Rather than transcribe the losing declaration, `kbd.css` carries what the utility resolved to as a plain rule — `:where([data-slot="input-group"], .ds-input-group) .ds-kbd { background: color-mix(in oklab, var(--ds-ink-faint) 10%, transparent) }` — and drops the source's `var(--input)` line. Batch 7 has nothing to undo. |
| 6 | plan measurement wrong | `toolbar.css` carried `.ds-toolbar .ds-input { min-width: 200px }`, one of the **five** `.ds-input` descendant overrides batch 7 owes a propagation pass (batch-plan §4 batch 7, listing `color-picker.css:54`, `time-picker.css:13`, `toolbar.css:38`, `date-picker.css:16`, `date-range.css:17`). The wholesale replacement of `toolbar.css` deletes it — the replacement is `.ds-toolbar-input`, which sets its own width. **Batch 7 must reach four sites, not five.** |
| 6 | source omission, fixed forward | The source has **no indeterminate rendering for `progress`** — no stripe, no sliding segment, nothing keyed off Base UI's `data-indeterminate`. Absorbing it verbatim would have dropped a state 0.11 could draw and left `value={null}` as a blank track. `progress.css` keeps the animation, keyed off both `[data-indeterminate]` and 0.11's `--indeterminate` modifier, so the React binding and hand-written HTML land on the same rendering. |
| 6 | source defect, fixed forward | `empty.tsx`'s `EmptyDescription` was typed `React.ComponentProps<"p">` and rendered a `<div>`, and `EmptyMedia` rendered `data-slot="empty-icon"` under the name `media`. Both corrected in the absorbed component: a real `<p>`, and `data-slot="empty-media"`. |
| 6 | scope call, recorded | Three 0.11 renderings are **preserved** rather than replaced, each because a wholesale swap would have unstyled a committed fixture with no React component on either side to re-class it. (a) `table.css` keeps the whole element grammar — `.ds-table th/td`, `--hover`, `__num`, `__name`, `__row-action` — beside the source's part grammar, kept apart by `:not(.ds-table-head)` / `:not(.ds-table-cell)` guards and a `.ds-table-container > .ds-table` rule that drops the frame for the composed component; the plan names this one. (b) `spinner.css` keeps the drawn ring under `:not(svg)`, because the React binding spins a Phosphor glyph and hand-written HTML has no glyph to spin — without it every non-React consumer got an invisible rotating box. (c) `.ds-toolbar-spacer` survives the rename, because a hand-written full-width bar still has free space to eat even though the composed `<Toolbar>` is `width: fit-content`. |
| 6 | scope call, recorded | `stepper.tsx` renders **0.11's classes**, not the source's, because `stepper.css` is a cross-boundary pin held by `Wizard` — the plan requires this. Two consequences: there is **no `StepperSeparator`** (the connector is a `::after` on the step, so a separator element would style nothing), and `stepper.css` gains two additive blocks — `.ds-stepper__content { display: contents }` and a `[data-orientation="vertical"]` grid. Neither can reach `Wizard`, which renders no wrapper and no orientation attribute. |
| 6 | scope call, recorded | `examples/demo/` — the signed-in console — keeps the 0.11 prop shapes through a new demo-local `examples/demo/compat.js`, rather than rewriting ~35 hand-written `React.createElement` call sites onto the parts. Nothing in it ships (`examples/` is not in `package.json`'s `files`), and the component pages under `examples/components/` teach the real API. Rewriting the demo onto the parts is a 1.0 cutover item. |
| 6 | pre-existing, not a batch 6 regression | `tests/a11y.spec.js`'s `a11y: demo (signed-in console)` fails on `batch/5-charts-net-new` as well: the demo loads React from esm.sh at runtime and never reaches its sign-in button without network. Verified by stashing the batch and re-running. |
| 6 | incumbent defect, fixed forward | The incumbent `Checkbox` (held until batch 7) destructured a fixed prop list and dropped everything else, so `aria-label` never reached the `<input>`. A checkbox in a selection column has no visible text, so that is its only possible name — `table/selectable` failed axe's `label` rule on it. The applier now spreads its remaining props onto the input. Two lines, in a held component, because the alternative was a demo that fails the gate. |
| 6 | source rule dropped, deliberately | The source's `Stepper` makes the horizontal rail a tab stop, citing axe's `scrollable-region-focusable`: its own CSS lets the row overflow, and a rail with nothing focusable inside is then unreachable by keyboard. The held stylesheet gives every step `flex: 1 1 0; min-width: 0`, so the row shrinks rather than scrolling and the stop would have led nowhere. Dropped, and `site/tests/stepper-regress.spec.ts` asserts its absence alongside the connector. |
| 6 | global defect, fixed forward | `css/themes/dark.css` overrode every `--ds-*-bg` tint but none of the `--ds-*-ink` shades, which are tuned as dark text on the *light* tints. In the dark theme that left dark ink on a dark tint — `.ds-tag--success` and `.ds-banner--info` measured under 2:1. The four ink tokens now have dark-theme mirrors, each clearing 4.5:1 on its own tint, on `--ds-bg` and on `--ds-surface`. Fixed in the token layer rather than in `banner.css`, because `tag.css` and `chip.css` read the same family and `tag.css` is frozen — one four-line override fixes all three without touching a frozen contract. |
| 6 | pre-existing, newly exposed | The dark-theme `.ds-button--primary` contrast defect ([#15](https://github.com/LittleBigCode/design-system/issues/15)) now shows on `stepper` and `pagination` as well, because both batch 6 demos use a primary button. `button.css` is a frozen file batch 7 owns and is untouched here; the same failure already stands on `wizard`, `split-button`, `alert-dialog`, `toggle-group` and `theme-switcher`, none of which this batch touches. |
